# Architecture

Module-by-module reference for the code: what each package and module does, how they depend on each other, and the design notes behind them.

```
optionpricing/          the library, one importable package (pip install -e .)
  core/                 GBM simulator, pricer base class, generic metrics
  pricing/european/     Black-Scholes, Monte-Carlo
  pricing/american/     binomial trees (CRR, batch BBSR), Longstaff-Schwartz, basis functions
  hedging/              Deep Hedging building blocks: risk measures, transaction costs, settlement, scenario simulator, exercise dates, P&L, baselines (rebuild in progress)
  hedging/legacy/       SAC's hedging env, option value functions, baselines, P&L evaluation
  ml/surrogate/         MLP surrogate pricer: tree/ (current), legacy/ (LSM-trained), chunks.py
  ml/hedging/legacy/    SAC agent: policy, critics, replay buffer, training loop
  ml/experiments/       research drivers (ablation runner)
scripts/                one module per main.py subcommand
tests/                  unit/, integration/, mutation/, helpers.py
docs/                   this file, results/
main.py                 the CLI entry point
artifacts/              generated: data/, checkpoints/, logs/, runs/ (gitignored)
notes/                  personal notes: REMINDER.md, course/ (gitignored)
```

Dependencies point one way: `core` <- `pricing` <- `hedging` <- `ml`; `scripts/` and `main.py` sit on top. Nothing in the package imports `scripts/` or `tests/`.

## Environment

Pinned versions in `requirements.txt` match the environment this was developed against (Python 3.13, PyTorch 2.11 CPU build). No GPU is required: the training loops check `torch.cuda.is_available()` at runtime and fall back to CPU.

## Command reference

Everything is driven through `main.py`, a thin `argparse` subcommand dispatcher. Each subcommand's flags and logic live in `scripts/<name>.py`; `main.py` itself contains no pricing/training logic. Run from the project root so the absolute module imports resolve (e.g. `from optionpricing.core.gbm import GBM`):

```
python main.py <command> [options]
python main.py --help                 # lists all commands
python main.py <command> --help        # lists that command's flags
```

Commands:
- `price` — compare pricing models. `--option_class {EU,US,both}` picks Black-Scholes+Monte-Carlo vs Binomial-tree+Longstaff-Schwartz vs both. Also: `--option_type {call,put}`, `--strike`, `--start_price`, `--sigma`, `--risk_free_rate`, `--maturity`, `--sampling`, `--nb_predictions`, `--nb_steps`, `--reg_type {simple,laguerre}`, `--max_degree`, `--plot`.
- `train-ml` — train the tree MLP surrogate (`optionpricing.ml.surrogate.tree.tree_training.train_surrogate`) on `--dataset_path` (default `artifacts/data/tree_put_dataset.npz`) and save the best-validation `PutSurrogate` to `--checkpoint_path` (default `artifacts/checkpoints/put_surrogate.pth`, `test-ml`'s default). One flag per `TrainConfig` field, named like it, defaults read from it (`scripts/train_ml.train_config` builds the config, so a bad value raises `TrainConfig`'s `ValueError` before any work; a unit test fails if a field has no flag): `--depth`, `--width`, `--activation`, `--output`, `--split_ratio`, `--valid_ratio`, `--batch_size`, `--epochs`, `--lr`, `--lr_min`, `--patience`, `--lbfgs_steps`, `--lambda_delta`, `--lambda_shape`, `--shape_points`, `--seed` (see `tree_training.py` below for what each does). `--split_ratio`/`--seed` must be passed to `test-ml` too if changed. Trains on CUDA when available. Prints the checkpointed entry's validation loss, its premium and delta terms apart, and the premium/delta RMSEs.
- `test-ml` — evaluate a trained `PutSurrogate` (the tree MLP, `--checkpoint_path`, default `artifacts/checkpoints/put_surrogate.pth`) with `optionpricing/ml/surrogate/tree/tree_evaluation.py`: on the test split of `--dataset_path` (default `artifacts/data/tree_put_dataset.npz`; `--split_ratio`/`--seed` must be the training run's, defaults equal `TrainConfig`'s) against the teacher's labels, and on a factorial grid (`--n_z`, `--n_sigma`, `--n_T`, `--rates`) against an independent reference tree (`--ref_method`, `--ref_steps`, default BBSR 4000, ~48 ms per option; a reference with the dataset teacher's `method`/`nb_steps` raises a `ValueError` before any work; `--reference_cache path.npz` loads the grid's reference tree and vega from that file, or computes and writes it, ~2 min saved per model, refused if built for other grid/reference settings). Prints per-bucket tables (continuation rows by `|z|`, `T` and `r`, exercised rows apart; $ at K = 100, relative and implied-vol errors only where meaningful, delta/gamma errors, the theta-PDE gap, the payoff-floor rate), no-arbitrage violation rates above `--violation_tol` for the continuation and exercised regions apart (several values, e.g. `--violation_tol 1e-4 1e-5`, give one table each), the out-of-domain routing errors, and the time per price. Puts only: an American call without dividends is Black-Scholes.
- `train-hedge-legacy` — train the RL delta-hedging policy (`optionpricing/ml/hedging/legacy/`, in the `optionpricing/hedging/legacy/` environment). Flags: `--n_episodes`, `--warmup_steps`, `--update_every`, `--grad_steps_per_update` (gradient steps per triggered update, default `1`), `--lr` (Adam learning rate for actor + critics, default `1e-4`), `--alpha` (SAC entropy coefficient, default `0.2`), `--replay_buffer_size` (default `100_000`), `--prop_tc` (proportional cost `tc * |trade| * S_t`, default `0.001`), `--fixed_tc` (flat per-trade cost added to the hedging env, default `0.0`), both applied to the training and the validation env, `--risk_lambda` (mean-variance reward-shaping coefficient applied to the *scaled* reward, default `1.0` — must be `> 0` for the policy to have any reason to hedge, see `BUGS.md`), `--reward_mode {terminal,accounting}` (default `accounting`), `--gamma` (SAC discount, default `1.0`), `--reward_scale` (default `100`), `--auto_alpha/--no-auto_alpha` (learned entropy coefficient, default on; `--alpha` is then its initial value, `--alpha_lr` its learning rate, defaulting to `--lr`), `--val_paths` (default `1000`; held-out paths the checkpoint is selected on, `0` falls back to the trailing-50 training reward), `--val_every` (default `50`), `--val_metric {std,cvar}` (default `std`), `--val_seed` (default `--seed + 1000`; the validation env is built before the training simulation because `GBM` reseeds the global `np.random`), `--action_mode {residual,gap_fraction,band}` (default `residual`; see `policy.py` below - `gap_fraction` or `band` are the ones to use under trading costs; `band` builds a 2-D policy and matching critics), `--band_max` (default `0.2`, the widest no-trade band half-width in `band` mode; saved in the checkpoint), `--residual_scale` (default `0.1`: the policy learns a correction to the LSM delta, `hedge = clip(delta + residual_scale * tanh(u), -1, 1)`; `0` makes it output the hedge ratio directly; saved in the checkpoint), plus the usual pricing params (`--sigma`, `--strike`, `--reg_type`, etc.) used to build the GBM simulation and the Longstaff-Schwartz model the hedging environment wraps (`--sigma` is also passed to it, for the Black-Scholes delta feature of its delta regression; its European control variate is enabled for `--option_type call` only). Saves to `--checkpoint_path` (default `artifacts/checkpoints/best_policy_model.pth`).
- `test-hedge-legacy` — evaluate a hedging policy: mean P&L, std P&L, 95% VaR and 95% CVaR over `--n_episodes` simulated hedging episodes. `--policy {rl,delta,delta_band,no_hedge}` (default `rl`) selects between the trained RL policy (loaded from `--checkpoint_path`), an analytic delta-hedge baseline, a delta hedge with a no-trade band (`--band`, default `0.05`; `--band_target {delta,edge}`, default `delta`), and a no-hedge baseline (`optionpricing/hedging/legacy/baselines.py`) — the baselines need no checkpoint. `--prop_tc`, `--fixed_tc` and the Longstaff-Schwartz params (same defaults as `train-hedge-legacy`) should match the values used for the `rl` policy's training run for a fair comparison across `--policy` values (`residual_scale`, `band_max`, the action mode and the action dimension need no flag: they are read from the checkpoint, the dimension via `optionpricing.ml.hedging.legacy.policy.checkpoint_action_dim`). Reseeds `np.random` from `--seed` right before evaluation so runs with the same `--seed` across `--policy` values see identical simulated paths, for a fair comparison.

Dataset generation for the MLP surrogate is a separate entry point and **must be run as a module, not a script path** (it uses absolute imports like `from optionpricing.core.gbm import GBM`, which only resolve when the project root is on `sys.path` — `python -m` does this, `python optionpricing/ml/surrogate/tree/generate_tree_dataset.py` does not). The surrogate pipeline is `python -m optionpricing.ml.surrogate.tree.generate_tree_dataset`, then `python main.py train-ml`, then `python main.py test-ml`:

```
python -m optionpricing.ml.surrogate.tree.generate_tree_dataset [--n_rows N] [--chunk_size N] [--nb_steps N] [--method crr|bbs|bbsr] [--nb_jobs N] [--seed N] [--T_min T] [--exercised_keep F] [--output_dir artifacts/data]
```

Both generators (this one and the legacy LSM one below) are resumable through `optionpricing/ml/surrogate/chunks.py`: finished chunks are saved one file each, a re-run of the same command after an interruption (Ctrl-C, a kill) skips them, at most one chunk of work is lost, a stored `config.json` makes a resume with different settings raise a `ValueError`, the chunks are deleted once the dataset is assembled, and a redone chunk is identical to the original.

`--n_rows` (default `2**19`) and `--chunk_size` (default `1024`) must be powers of 2 (the Sobol points' balance holds exactly there). Each row is an American put per unit of strike, labelled by `price_put_batch` (`--nb_steps 1000`, `--method bbsr`), with Sobol-sampled parameters over a fixed domain (`DOMAIN` in the module: `T` 1 week to 5 years, `sigma` 0.05-0.6, `r` 0-0.08, `z = ln(m)/(sigma sqrt(T))` in [-3.5, 3], `m` in [0.4, 2.5]). It writes `<output_dir>/tree_put_dataset.npz` with *raw* columns only (`m`, `T`, `r`, `sigma`, `z`, `price`, `european_price`, `delta`, `gamma`, `exercised`) plus the settings (`teacher="tree"`, `nb_steps`, `method`, `seed`, `sampler="sobol"`, `n_rows`, `exercised_keep`, `pool_rows`, the domain ranges); no normalization stats, features are built at load time. Two flags make the dataset ablations' datasets (`docs/results/surrogate-training.md`), each still `--n_rows` rows: `--T_min` (default 1 week) starts the domain's T range there (`domain_from`, stored as the file's `T_range`, so a model trained on it routes shorter maturities); `--exercised_keep` (default 1, in (0, 1]) labels a pool of `2 * n_rows` Sobol points (`pool_rows`) and saves the first `n_rows` of those `thin_exercised` keeps, every continuation row and that share of the exercised ones. Chunks go to `<output_dir>/tree_chunks/`, not the LSM generator's `chunks/`. Tree settings the pricer would reject (`--nb_steps`/`--method`) fail before `config.json` is written (`check_teacher` prices the domain's corner puts first), so a corrected re-run is not refused as "other settings".

The legacy LSM surrogate's dataset (`optionpricing/ml/surrogate/legacy/`, no CLI consumer) has the same rules:

```
python -m optionpricing.ml.surrogate.legacy.generate_lsm_dataset [--path_per_sim N] [--nb_param_comb N] [--samples_per_param N] [--nb_jobs N] [--sampling N] [--option_type call|put|both] [--reg_type simple|laguerre] [--max_degree N] [--output_dir artifacts/data] [--seed N] [--chunk_size N]
```

The parameter draw is seeded (`--seed`, default `42`; sample `i`'s paths use seed `--seed + i`, so labels reproduce too), chunks of `--chunk_size` (default `1000`) samples go to `<output_dir>/chunks/`. It parallelizes LSM pricing (via `joblib`) across randomly sampled `(S0, K, sigma, r, T)` combinations, simulating each once and writing one row per option type (`--option_type both`, the default, gives a call and a put row; calls are labelled with the control-variate LSM, i.e. exactly Black-Scholes, puts with plain LSM; `--reg_type` defaults to `simple`, like every other LSM consumer), to build `<output_dir>/american_option_dataset.npz` (besides `features` and `label` it stores the LSM settings of the labels: `reg_type`, `max_degree`, `path_per_sim`, `sampling`), along with the feature-normalization stats in `<output_dir>/features_norm.npz` that `AmericanOptionDataset`'s consumers need to build inputs for new queries.


## Test layout

```
python -m pytest tests/                 # everything
python -m pytest tests/unit             # fast, no training/simulation-heavy work
python -m pytest tests/integration      # convergence checks + CLI smoke tests; slower
```

- `tests/unit/` tests individual components in isolation (closed-form formulas, basis-function derivatives against finite differences, dataset splitting, the hedging environment's reward arithmetic, etc.).
- `tests/integration/` checks components together: Monte-Carlo converging to Black-Scholes, Longstaff-Schwartz converging to the Binomial tree for American puts, the hedging baselines on tree deltas (`test_baselines_vs_tree.py`), and `test_cli_smoke.py`, which actually invokes `python main.py <command>` as a subprocess for each command — this is what catches import/wiring mistakes across `main.py` → `scripts/` → the library packages that unit tests (which import modules directly) would not.
- `tests/helpers.py` holds what several test files share — use it rather than redefining: `make_fake_lsm` (a fitted-LSM stand-in for `HedgingEnv`), `make_state` (a state in the env's layout), `parse_script_args` (a `scripts/` module's real parser defaults plus overrides, so new flags need no test edits) and `run_cli`/`run_python` (subprocess runs from the project root) and `write_tree_dataset` (a small real `generate_tree_dataset` file, 50-step trees, for the tree-dataset and training tests; `extra` passes more generator flags, e.g. `("--T_min", "0.25")`). The legacy hedging stack's tests live in `tests/unit/hedging_legacy/` and `tests/integration/hedging_legacy/`, and the fake envs/buffers shared by its `test_hedge_*.py` files in `tests/unit/hedging_legacy/hedge_fakes.py`. There is no `conftest.py`, as no fixture is shared yet. `pytest.ini` puts the project root on `sys.path` (`pythonpath = .`), which is what makes `from tests.helpers import ...` resolve.
- `tests/mutation/` holds hand mutation checks, not pytest files (no `test_` prefix): `python -m tests.mutation.tree_evaluation_mutants` applies small plausible bugs to `optionpricing/ml/surrogate/tree/tree_evaluation.py` one at a time and reruns `tests/unit/test_tree_evaluation.py`, which must fail for each (~5 s per mutant; the source is restored after each, and checked byte-identical at the end). A surviving mutant is a behaviour no test pins down.
- Tests follow their module: the legacy pipeline's are `test_lsm_model.py`, `test_lsm_dataset.py`, `test_lsm_training.py`, `test_lsm_evaluation.py`, `test_generate_lsm_dataset.py` (unit) and `test_lsm_pipeline.py` (integration, generator -> `train_legacy_mlp`); `test_chunks.py` covers `optionpricing/ml/surrogate/chunks.py`. `train-ml` -> `test-ml` end to end on a tiny tree dataset is in `test_cli_smoke.py`; the ablation runner's pure parts in `tests/unit/test_run_ablations.py`, end to end (worker processes, rerun skip, settings mismatch, a dataset variant on the `--grid_T_min` grid) in `tests/integration/test_run_ablations.py`.
- `optionpricing/ml/surrogate/legacy/lsm_evaluation.py` holds `regression_tests`/`test_option_price_lsm` (the legacy LSM pipeline's evaluation, no CLI caller). These are evaluation helpers, not pytest tests — don't confuse them with `tests/`, nor `tree_evaluation.py`'s `evaluate_*` functions.


## Modules

Pricing is split by option class (`pricing/european/`, `pricing/american/`), everything else by role.

- `optionpricing/core/` — the foundation every pricer depends on: `metrics.py` (generic, model-agnostic metrics `mse_fn`, `mae_fn`, `r2_fn`, `accuracy_fn`, used by the legacy surrogate's `lsm_model.py`/`lsm_evaluation.py`), `gbm.py` (`GBM`, the Geometric Brownian Motion path simulator. `simulate_paths(nb_predictions, maturity, sampling)` returns time last: `(nb_predictions, n_steps + 1)` for one contract, or `(n_contracts, nb_predictions, n_steps + 1)` when `sigma`, `start_price` or `risk_free_rate` is an array of one value per contract (numbers and per-contract arrays mix; arrays of different lengths or 2-D raise `ValueError`), so `paths[c, p, k]` is contract `c`, path `p`, step `k`. `n_steps = int(round(maturity * sampling, 9))` (rounded so float error cannot drop a step, B-040). Step 0 is the start price and the last step sits exactly at `maturity`, `maturity / n_steps` apart. An int `seed` reseeds the global `np.random`, as the existing results were made, and draws the same numbers as the earlier time-first version; a `np.random.Generator` is drawn from and leaves the global state alone. `LongstaffSchwartz`, `MonteCarlo` and `HedgingEnv` take the same time-last `(n_paths, n_steps + 1)` array, use the `maturity / n_steps` spacing and treat the last step as expiry) and `base.py` (`OptionPricing`, an ABC with one abstract method `calculate_option_price(T)`). `BlackScholes`, `MonteCarlo`, `BinomialTree`, and `LongstaffSchwartz` all subclass it.
- `optionpricing/pricing/european/` — `black_scholes.py` (closed form: vectorized functions `black_scholes_price`/`black_scholes_delta`/`black_scholes_gamma`/`black_scholes_vega`/`black_scholes_dT(start_price, strike, maturity, risk_free_rate, sigma[, option_type])` (`dT` is the derivative in the time to maturity, i.e. minus theta), every argument an array if needed — use these for batches; the `BlackScholes` class wraps them for an option priced at several times to maturity) and `MonteCarlo` (path-average payoff), both taking `option_type` in `{call, put}` (validated eagerly in `__init__`).
- `optionpricing/pricing/american/`:
  - `BinomialTree` — Cox-Ross-Rubinstein tree with backward induction; American exercise is baked into the payoff recursion via `np.maximum(exercise, continuation)`. `calculate_option_price()` requires `predict_payoff()` to have been called first (raises `AttributeError` otherwise — there's no silent default).
  - `LongstaffSchwartz` — the core LSM implementation. It takes the simulation time last, `(n_paths, n_steps + 1)`, and exposes `payoff`, `continue_val` (both `(n_paths, n_steps + 1)`), `delta` and `gamma` (`(n_paths, n_steps)`, none at expiry) time last too. The backward induction reads and writes one step of every path at a time, so it works on private step-major copies (`_by_step`, `_payoff`, ...), where a step is contiguous in memory; the public arrays are transposed views of them (reading a time-last array one step at a time made an American put on 50,000 paths x 252 steps ~13% slower, 1.88-1.90 s against 1.63-1.68 s). `predict_payoff()` walks the simulation backward; at each timestep `fit()` regresses continuation value on in-the-money paths only (`itm_mask`), using either simple polynomial or Laguerre polynomial basis functions (from `basis_functions.py`) of degree `max_degree`. It also stores per-path, per-timestep Greeks (`self.delta`, `self.gamma`) from a *separate* regression, over all paths (not just ITM), of each path's pathwise delta — the derivative of its discounted cashflow under the fitted exercise rule with respect to `S_t`, i.e. `±S_stop/S_t` discounted if the path pays off, else 0. Gamma is the analytic derivative of that fit (the basis derivatives are checked against finite differences in `tests/unit/test_basis_functions.py`). When `sigma` is given, the European Black-Scholes delta is an extra feature of that regression (and its gamma the matching derivative feature): a low-degree polynomial alone can't follow delta's steepening near expiry. Differentiating the ITM-only continuation fit instead — the original approach — extrapolates to OTM paths and gave deltas in the tens; ridge/moneyness-bin regressions tried as a fix for that made delta ~0 and caused spurious early exercise, and were removed (see `BUGS.md`). `control_variate` (default `False`, requires `sigma`) uses the European option as a control variate: the continuation regression targets the realized cashflow minus the realized discounted European payoff, and the exact Black-Scholes price is added back (also in `calculate_option_price`). Non-early-exercised paths then contribute exactly 0, which removes the regression noise that makes plain LSM spuriously early-exercise American calls near expiry (a ~0.1 continuation-vs-intrinsic margin against ~0.15 fit noise). It's off by default because for puts the plain rule was as good or better out of sample; `train-hedge-legacy`/`test-hedge-legacy` enable it for calls only. `self.exercise_time` records each path's exercise index under the fitted rule, consumed by `optionpricing/hedging/legacy/env.py` to decide episode length. `calculate_option_price` ignores its `T` argument by design (the American price comes from the simulated payoff at t=0, not from an external time-to-maturity).
  - `batch_binomial_tree.py` — `price_put_batch(moneyness, maturity, risk_free_rate, sigma, nb_steps=1000, method="bbsr", american=True, chunk_size=None)`, a vectorized tree pricer for *batches* of puts per unit of strike (K = 1), returning `TreeResult(price, delta, gamma, exercised)` (delta/gamma from the level-1/2 nodes; a put exercised today, i.e. priced at its payoff `1 - m` with `m < 1`, gets the exact price `1 - m`, delta `-1` and gamma `0` instead, which the finite differences miss just inside the exercise region, see `BUGS.md`; `exercised` is the boolean mask of those puts, all `False` with `american=False`). `method="crr"` is the same recursion as `BinomialTree` (equal to ~1e-14); `"bbs"` values the last step with Black-Scholes (`black_scholes_price` with strike 1), and `"bbsr"` (default) adds Richardson extrapolation `2 P(N) - P(N/2)`, which removes CRR's odd/even zig-zag in N. `chunk_size` (options stepped together per pass, `None` = whole batch) only affects speed: the tree dataset generator passes 32 and explains why. The MLP surrogate's teacher; `BinomialTree` stays for the `price` command. `exercise_boundary(maturity, risk_free_rate, sigma, nb_steps=1000, method="bbsr", chunk_size=None)` returns the American put's early-exercise boundary `S*/K` per contract, shape `(*batch, nb_steps + 1)`, entry `i` at time `i * maturity / nb_steps`: the hedging rebuild's exercise rule (`docs/results/hedging-training.md`). The same induction (`_induct`) records, per level, where "hold minus exercise" crosses zero between the highest node where exercising wins and the node above, capped at 1. Its tree starts at `m = 1` (the boundary does not depend on the spot) with `_nb_extra_nodes` nodes added below every level, enough to reach the perpetual put's boundary `2r / (2r + sigma^2)`, so the levels near today are bracketed too; they leave the plain tree's values bit for bit. The last entry (expiry) is 1, entries before it are NaN when `r <= 0`, and `"bbsr"` uses the finer BBS tree, so it equals `"bbs"`. Validation is shared with `price_put_batch` (`_validated_params`).
  - `basis_functions.py` — `simple_poly`/`simple_poly_deriv_k` and `laguerre_poly_gen`/`laguerre_deriv_k`, factored out of `LongstaffSchwartz` so the basis math (and its derivatives) can be unit-tested independent of the pricing class.
- `optionpricing/ml/` — everything that is learned. `optionpricing/ml/` depends on `optionpricing/hedging/` (the env it trains in, `cvar`), never the other way round:
  - `surrogate/` — the MLP surrogate pricer and its data:
    - `tree/` — the binomial-tree-trained put surrogate, what `train-ml`/`test-ml` run; files are `tree_`-prefixed (the generator `generate_tree_dataset.py`) so they never read as the legacy pipeline's:
      - `generate_tree_dataset.py` — the tree-labelled put dataset of the MLP surrogate (`docs/results/surrogate-training.md`), run as `python -m optionpricing.ml.surrogate.tree.generate_tree_dataset` (see "Command reference" above). `sobol_points(n, n_dims, seed)` (scrambled Sobol, power-of-2 counts only; `main` passes `len(SAMPLED)`, the module's tuple of sampled parameters in column order, `("T", "sigma", "r", "z")`) → `map_to_domain` (reads its columns by name from `SAMPLED`, raises on a width mismatch; `T`/`sigma` log-uniform, `r` uniform, `z = ln(m)/(sigma sqrt(T))` uniform on each draw's interval within `DOMAIN`'s z range and `m` cap, so the `T`/`sigma`/`r` marginals stay as specified) → `label_puts` (`price_put_batch` with `chunk_size=32`, plus the Black-Scholes European price). `domain_from(T_min, domain=DOMAIN)` is a copy of the domain with its T range starting at `T_min` (`ValueError` outside the range), passed to `check_teacher`, `generate_tree_chunks` and `map_to_domain`; `thin_exercised(exercised, keep, n_rows)` returns the indices of the first `n_rows` rows kept when every continuation row and the exercised row of rank j with `floor((j + 1) keep) > floor(j keep)` are (evenly spaced; every row at keep 1), `ValueError` if fewer remain. Uses the chunk helpers of `chunks.py` (`prepare_chunk_dir`, `save_chunk`, `chunk_file`, `n_chunks_for`, `tqdm_joblib`), shared with the legacy LSM generator; one joblib job per chunk.
      - `tree_dataset.py` — `TreePutDataset`, a `torch.utils.data.Dataset` that loads `tree_put_dataset.npz` (raises `ValueError` on a file without `teacher="tree"` or a needed column, and on `split_ratio` outside [0, 1]), does a seeded shuffle-then-split, so train/test constructed with the same seed are guaranteed disjoint (not grouped by parameter draw: each row is its own draw), and builds everything at load time. Inputs are `build_features(m, T, r, sigma)`, the 6 columns of `FEATURES` (`log m`, `log T`, `log sigma`, `r`, `sigma sqrt(T)`, `z`), in torch so autograd flows through; its inputs broadcast together (an array of `m` with scalar `T`, `r`, `sigma` works). Use this one function wherever the net is fed, never a copy. They are standardized by a `FeatureStats` (mean/std) fitted on the *training* split for either split (an empty training split raises unless `stats=` is given), with `to_dict`/`from_dict` for storing it with the model (`from_dict` raises if the feature names differ from `FEATURES`). Items are `(features, features_dm, premium, premium_dm)`, each value followed by its derivative in `m`: `features_dm` = d (standardized) features / d m (autograd), so the net's delta in `m` is its input gradient dotted with it; premium = `price - european_price` (per K); `premium_dm` = tree delta - BS put delta. Also exposes `params` (raw `m, T, r, sigma`), `exercised` and `domain` (the file's `*_range` keys).
      - `tree_model.py` — `MLP`, the tree-trained net: `depth` hidden layers (default 4) of `width` units (default 128), each followed by `activation` (a key of `ACTIVATIONS`, default `"silu"`: smooth, so the autograd delta/gamma are meaningful; `"relu"` is only there for the ablation), then a linear layer to one output, the early-exercise premium `(American - European) / K`, optionally through a softplus (`output="softplus"`, forces it > 0). Inputs are the `len(FEATURES)` standardized columns of `tree_dataset.py`'s `build_features`. No BatchNorm/Dropout: a row's output depends on that row only, which `tree_pricer.py`'s sum-then-grad Greeks rely on. `MLP.config` holds the constructor arguments, so a checkpoint can rebuild the same net (`MLP(**config)`). Trained by `train-ml`, scored by `test-ml`.
      - `tree_pricer.py` — `PutSurrogate(model, stats, domain)`: the one place a price is reconstructed from the net. `price(m, T, r, sigma)` (broadcasting, per unit of strike) returns `SurrogateResult(price, delta, gamma, route)` with the TreeResult conventions (delta = dV/dS, gamma = K d2V/dS2): Black-Scholes European + the net's premium, and the BS Greeks + the premium's autograd derivatives in m. Queries outside `domain` (the dataset's `*_range` keys, `DOMAIN_KEYS`) are routed instead of extrapolated, `route` naming each one's source (`ROUTES`): with `T`, `sigma`, `r` inside, `z` above its range -> Black-Scholes and `z` below it with `r >= EXERCISE_MIN_RATE` (0.005) -> exercised today (`1 - m`, -1, 0); a net price below the payoff `max(1 - m, 0)` -> the payoff (route `payoff_floor`, delta -1 in the money or 0, gamma 0: an American put is never worth less than exercising now; it cut the test price MAE 25-35% on trial runs); everything else outside (incl. `m` beyond its cap) -> `price_put_batch` (BBSR, 1000 steps, `chunk_size=32` for speed). Invalid input (non-finite, or `m`/`T`/`sigma` <= 0) is kept out of every other route, `m` explicitly via `m_valid` since the z rules alone would take `m = 0` (z = -inf) and `m = inf`, so it always reaches the tree, which raises `ValueError`. `save(path)`/`load(path)` keep architecture, weights, `FeatureStats.to_dict()` and domain in one file tagged `format="tree_put_surrogate"`; `load` refuses anything else (e.g. a `LegacyMLP` state_dict) with a `ValueError`.
      - `tree_training.py` — the tree MLP's training loop, what `train-ml` runs. `train_surrogate(dataset_path, TrainConfig(...), checkpoint_path=None, device=None)` returns `TrainResult(surrogate, history)`: the `PutSurrogate` with the best validation weights (saved to `checkpoint_path` on every improvement) and one metrics dict per epoch (`evaluate_labeled`'s `loss`, which picks the checkpoint and drives early stopping, and its two halves `premium_term` + `delta_term`, reported apart in the history and the progress bar because one can improve while the other worsens: an 800-epoch run lowered the loss by trading price for delta accuracy; plus `premium_rmse`/`delta_rmse`, `valid_`-prefixed). The `TreePutDataset` training split is split again, seeded, into trained rows and `valid_ratio` (0.2) validation rows; the test split is never read. Adam, per-step cosine decay `lr` -> `lr_min` (1e-3 -> 1e-5) over `epochs` (400: on 2^19 rows it beat 200 and 800 on price, see `docs/results/surrogate-training.md`) of `batch_size` (1024), early stopping on the validation labeled loss (`patience` 20, a safety net, counted only once the rate is within `PATIENCE_LR_FRACTION` (10%) of the way from `lr_min` to `lr`, i.e. the last ~20% of the cosine: at a higher rate the loss jitters, and a fixed patience cut 400-epoch runs short, see `BUGS.md`), optional full-batch L-BFGS finish (`lbfgs_steps`, 0 = off; kept only if validation improves; gradient accumulated over `EVAL_CHUNK`-row chunks). Loss (`labeled_loss`): premium MSE / var(premium) + `lambda_delta` (default 0.3) * delta MSE / var(premium_dm), the delta being the net's input gradient dotted with `features_dm` (`premium_and_delta`); + `lambda_shape` (default 0: no measurable gain even with the scaling fixed, ~3.4x the step time) * `shape_penalty` on `shape_points` fresh random domain points per step (`ShapePoints`): squared `shape_violations`, i.e. relu of `w m dV/dm`, `-w^2 m^2 d2V/dm2`, `-T dV/dT`, `-sigma dV/dsigma` (`w = sigma sqrt(T)`: the `w` factors make the m terms price changes over a one-sigma move; without them convexity was ~3000x the labeled loss, see `BUGS.md`) of the *full* price (BS closed-form derivatives + the net's by autograd; `SHAPE_CONDITIONS` names the columns; the derivatives come from `price_derivatives`, which `tree_evaluation.py` reuses, and `scaled_violations` applies the scaling), / var(premium); L-BFGS uses a fixed pool of as many points as training rows. `TrainConfig` validates its fields (`ValueError`) and seeds the split, init, batch order and shape points from `seed`; its defaults are the configuration the seeded ablations chose (`lambda_delta` 0.3, `output="softplus"`, width 128; `docs/results/surrogate-training.md`), the shipped model's. The net starts from `initial_model(config, premium)`: the seeded MLP, with, for the softplus output only, the output layer's bias term set to `log(expm1(mean premium))` of the trained rows, so the untrained net predicts the mean premium (initial premium term ~1 instead of ~500; `ValueError` if that mean is not positive; why: `docs/results/surrogate-training.md`, "Output initialization: start at the mean premium"). A run whose validation loss is never finite raises.
      - `tree_evaluation.py` — what `test-ml` runs on a `PutSurrogate`. `evaluate_test_split` (test split, labels rebuilt from the dataset's targets; raises if the dataset's domain is not the surrogate's) and `evaluate_grid` (`evaluation_grid`: z linear, sigma and T log-spaced over the surrogate's domain, z inset by 1e-9 so every point stays on the net route, points beyond the `m` cap dropped; `tree_prices` reference with a progress bar; `tree_vega`, central difference of BBSR-1000 trees at sigma ±1%, for the first-order implied-vol error |error| / vega) (both take `tols`, a sequence of violation tolerances; `evaluate_grid` takes `reference_cache` and `domain`, the grid's domain, the surrogate's by default, `ValueError` if it leaves the surrogate's: the dataset ablations score models trained on different T ranges on one grid) return dicts of `bucket_metrics` rows (`bucket_masks`: `Z_BUCKETS`/`T_BUCKETS` over continuation rows, then exercised, then all), `violation_rates` and, for the grid, route counts, `routing_queries` errors and `time_pricers`; `print_report` prints them. `grid_reference(domain, ref_steps, ref_method, n_z, n_sigma, n_T, rates, cache_path=None)` returns a `Reference(grid, tree, vega, seconds_per_option)`, the model-independent part (~2 min); with `cache_path` it loads that `.npz` if it exists (the stored `reference_settings`: domain, grid sizes and rates, reference tree, vega trees and bump; other settings raise `ValueError`) or computes and writes it atomically. `violation_rates_by_tol` gives `{tol: violation_rates}`; results store violations that way, and `print_report` prints one table per tolerance. `net_diagnostics` evaluates the *raw* net (no routing, no payoff floor): price, theta `-dV/dT`, the PDE theta `r V - r m delta - 1/2 sigma^2 m^2 gamma` and the scaled violations, through `training.price_derivatives`.
    - `chunks.py` — the resumable-generation helpers both generators share: `chunk_file`/`n_chunks_for` (one `chunk_XXXXX.npz` per chunk), `prepare_chunk_dir` (writes `config.json`, or raises `ValueError` if the stored one differs), `save_chunk` (atomic: written to a temp file, then `os.replace`d) and `tqdm_joblib` (a tqdm bar driven by completed joblib jobs).
    - `legacy/` — the original LSM-trained surrogate, kept as a library: no CLI command uses it (`train-ml`/`test-ml` run the tree MLP). Kept for the ablation against the old architecture and for rerunning the LSM comparison; files are `lsm_`-prefixed so they never read as the tree pipeline's:
      - `lsm_model.py` — `LegacyMLP`, the original net (5 inputs: `S0/K`, normalized T, normalized r, normalized sigma, `is_call` (raw 0/1, from `option_type_feature`) → 1 output: **time value** `(price - smooth_intrinsic_value) / K`, not raw price) trained as a fast surrogate for LSM. Predicting the residual over intrinsic value shrinks the target's dynamic range (deep ITM prices dwarf deep OTM ones), but `smooth_intrinsic_value` is a *softplus* approximation of `intrinsic_value`, not the exact `max(K-S,0)`/`max(S-K,0)` — see "Softplus reparameterization" below for why. `beta_frac` (default `0.06`) is a fixed constant baked into the function, not a CLI flag, to avoid it drifting out of sync between label generation and reconstruction. Anywhere that needs an actual price back from the model's output must add `smooth_intrinsic_value(...)` for the row's option type (see `lsm_evaluation.py::test_option_price_lsm`).

      - `generate_lsm_dataset.py` — parallel LSM-based dataset generation script, run as `python -m optionpricing.ml.surrogate.legacy.generate_lsm_dataset` (see "Command reference" above). `gen_rdm_params` samples moneyness (`S0/K`) log-uniformly and continuously over `moneyness_range` (default `(0.4, 1.6)`) rather than from a handful of discrete buckets — discrete buckets leave untrained gaps between them that the MLP then has to extrapolate across.
  - `hedging/legacy/` — a SAC (Soft Actor-Critic)-style continuous-control RL setup for delta hedging, trained in `optionpricing/hedging/legacy/env.py`:
    - `policy.py` — Gaussian policy network (actor): outputs `(mean, log_std)` → `torch.distributions.Normal`. The action is this distribution's sample (or, for deterministic evaluation, its mean) squashed into `[-1, 1]` via `tanh` — see `sac.py`'s `_squash` for why a hard clamp isn't used instead. `hedge_ratio(state, squashed)` maps that action to the hedge ratio the env receives, depending on `action_mode`. In `"gap_fraction"` mode it is `position + w * (delta - position)` with `w = (squashed + 1) / 2` in (0, 1), the fraction of the gap to delta closed this step; the mean output's bias starts at `w ≈ 0.9` (`_INITIAL_GAP_FRACTION`) so the untrained policy is almost a delta hedge, and holding still (w ≈ 0) is easy to represent, which matters under trading costs (see `BUGS.md`). In `"band"` mode (`action_dim` must be 2) the squashed action `(a0, a1)` gives a no-trade band half-width `b = band_max * (a0 + 1) / 2` and a rebalancing target `lam = (a1 + 1) / 2` (0 = band edge, 1 = delta): the position is held *exactly* while `|position - delta| <= b`, otherwise the hedge is `delta + sign(position - delta) * (1 - lam) * b`, clipped to `[-1, 1]`. A constant action is `baselines.delta_band`, which a unit test checks; the biases start at `b = 0.1 * band_max` (`_INITIAL_BAND_FRACTION`) and `lam = 0.9` (`_INITIAL_BAND_TARGET`). The mode is read back from the buffers via the `action_mode` property. In `"residual"` mode (default) it is `clip(delta + residual_scale * squashed, -1, 1)`, with delta read from the state at `_DELTA_IDX` (must match `HedgingEnv._get_state`'s layout, which a unit test checks), or the action itself when `residual_scale == 0`. The critics, replay buffer and entropy term all work on the squashed action, not the hedge ratio; delta is in the state, so nothing is lost. `residual_scale`, `gap_fraction` (1.0 in gap-fraction mode) and `band_max` (0 outside band mode) are registered buffers, so they are saved in the checkpoint; checkpoints predating them load as `residual_scale = 0`, residual mode and not band mode. `checkpoint_action_dim(state_dict)` reads the action dimension off a checkpoint's output layer, so a loader can build the matching network first. Together with validation checkpointing (`sac.py`), the residual form gets the RL policy 20-25% below the LSM delta hedge's P&L std on puts and level with it on calls (see `BUGS.md`, "RL hedging policy trails the LSM delta hedge").
    - `critic.py` — twin Q-networks (state+action → scalar), the standard SAC double-critic setup.
    - `replay_buffer.py` — plain deque-based replay buffer; actions are pushed as scalars or `(action_dim,)` vectors and sampled as `(batch, action_dim)`; `max_size` (default `100_000`) is exposed via `train-hedge-legacy --replay_buffer_size`.
    - `sac.py` — `_squash(dist)`: samples `dist` (reparameterized) and squashes it into `(-1, 1)` via `tanh`, applying the corresponding log-prob Jacobian correction. Used everywhere a sampled action feeds a critic (the Bellman target and the actor loss) instead of a hard `.clamp(-1, 1)` — a hard clamp has exactly zero gradient once a sample lands outside the range, which both freezes `mean` wherever it drifted to and lets the entropy term keep inflating `std` for free (nothing pulls a saturated policy back). `train()`: twin critics with frozen target copies (Polyak-averaged via `tau`) computing the Bellman target, a warmup phase of random actions (`warmup_steps`) before the policy starts driving exploration, gradient updates every `update_every` environment steps, and checkpointing. With a `val_env` (a terminal-mode `HedgingEnv` on held-out paths; `train-hedge-legacy` builds one unless `--val_paths 0`), the checkpoint is the policy with the best `val_metric` (`"std"`, the default, lower is better; or `"cvar"`, higher is better) over the terminal P&L of the first `val_paths` validation paths, i.e. the same numbers `test-hedge-legacy` reports. The untrained policy is scored and saved first (under the residual form it already hedges at delta), then the policy is re-scored every `val_every` episodes and after the last one, and replaces the checkpoint only on strict improvement. Without a `val_env`, it falls back to saving whenever the trailing 50-episode mean raw reward improves, which mostly measures which paths were drawn. `grad_steps_per_update` (default `1`, must be `>= 1`) runs that many critic/actor gradient steps — each on a freshly sampled batch — per triggered update. `reward_scale` (default `1.0`) multiplies the env reward first, and `risk_lambda` (default `0.0`) then shapes it: the critics/actor train on `x - risk_lambda * x**2` with `x = reward_scale * reward`. `auto_alpha` (default `False`) learns `log_alpha` toward `target_entropy` (default `None`, i.e. `-policy.action_dim`) instead of keeping `alpha` fixed. The `risk_lambda` penalty is a mean-variance-style penalty that penalizes large-magnitude rewards symmetrically, not just downside — it only penalizes *hedging error* when the env uses `reward_mode="accounting"` (in `terminal` mode it penalizes holding any position, see `BUGS.md`); `episode_reward` and the fallback checkpoint criterion stay on the raw, unshaped reward so training progress remains comparable to `test-hedge-legacy`'s P&L.
- `optionpricing/hedging/legacy/` — the hedging problem the SAC agent trains in, kept as a library for `train-hedge-legacy`/`test-hedge-legacy`. Its P&L has two open accounting bugs (`.claude/BUGS.md`, B-037 and B-038). The Deep Hedging rebuild (`.claude/PLAN.md`, "Hedging rebuild") puts its modules in `optionpricing/hedging/` itself (see the entry after this one):
  - `env.py` — `HedgingEnv` wraps a *fitted* `LongstaffSchwartz` instance (must call `predict_payoff()` first). State = `[S_t/K, t/(n_steps-1), delta, gamma, position]`, read from the LSM's time-last arrays (`simulation[path, t]`, `delta[path, t]`); episodes run per-path from `t=0` to that path's `exercise_time`; reward is hedge P&L minus transaction cost, minus the option payoff at exercise, all scaled by strike. Transaction cost has two components: `prop_tc` (proportional, `tc * abs(trade) * S_t`) and `fixed_tc` (flat, default `0.0`, charged whenever `abs(trade)` exceeds `_TRADE_EPS` so floating-point noise around holding the same position isn't charged). `reward_mode` (default `"terminal"`, the behavior just described) can be set to `"accounting"`, which also subtracts the option's value change `V_{t+1} - V_t` every step (V from a `value_fn(t, S)`, required in that mode, with the payoff replacing V on the exercise step), so each step's reward is the local hedging error; the episode sum then equals the terminal-mode sum plus the constant `V_0/K`. `train-hedge-legacy` uses `accounting`; `test-hedge-legacy` and the training validation env keep `terminal` so the reported P&L is unchanged. `reset(path_idx=None)` starts on a given path (random if None). `rollout_pnl(hedge_fn, path_idxs)` computes the terminal-mode P&L of one episode per path with all paths stepped together, so a policy is called once per time step for the whole batch (`hedge_fn` maps `(n, 5)` states to `(n,)` hedges). It shares `_trading_cost`/`_payoff` and `_build_states` with `step()`/`_get_state()` and replicates the rest of `step()`'s terminal-mode arithmetic (the position held before a trade earns that step's move) in vectorized form; a unit test checks the two agree, so any other change to `step()`'s P&L must be mirrored there.
  - `option_value.py` — value functions on the simulation's time grid for the accounting reward: `black_scholes_value_fn` (exact for an American call without dividends), `binomial_value_fn` (American, a CRR tree with `substeps` per simulation step, interpolated in log-price per step, floored at intrinsic), and `make_option_value_fn`, which picks BS for calls and the tree for puts. `n_steps` there is the simulation's step count, start and expiry included (`simulation.shape[1]`): step `t` has remaining time `(n_steps - 1 - t) * maturity / (n_steps - 1)`, the last step being expiry.
  - `baselines.py` — non-learned reference policies matching `evaluate()`'s `action_fn` signature: `delta_hedge` (hedge ratio = the LSM's own analytic delta, i.e. state index 2 - the "trust the model's Greek, no learning" baseline) `no_hedge` (always 0), and `delta_band(band, target)`, a factory returning a no-trade-band policy: hold the position while `|delta - position| <= band`, otherwise rebalance to delta (`target="delta"`, suits fixed costs) or to the nearest band edge (`"edge"`, Whalley-Wilmott style, suits proportional costs). A hold must return the position *exactly*, since `HedgingEnv` only skips the fixed cost when `|trade| <= _TRADE_EPS`. Under trading costs `delta_band` is the bar RL has to beat, not daily delta. Used via `test-hedge-legacy --policy {delta,delta_band,no_hedge}` to give the trained RL policy something to be measured against.
  - `evaluation.py` — `evaluate(action_fn, env, n_episodes)` is policy-agnostic - `action_fn` is a plain `state -> float` callable, not tied to `RLPolicy`'s Gaussian-actor `.mean` interface (the caller wraps a trained policy around `deterministic_hedge(policy, states)`, the shared deterministic action - `tanh(mean)` mapped through `hedge_ratio` - that validation also scores, e.g. `scripts/test_hedge_legacy.py`; a baseline from `baselines.py` already matches the signature directly). Returns `(mean_pnl, std_pnl, cvar_95)` in addition to printing them (plus the 95% VaR). `cvar(pnls, level=0.95)` is the expected shortfall, the mean of the worst 5% of P&Ls; before it existed, `evaluate()` reported the 5th percentile (the VaR) as "CVaR", so "CVaR" figures in older `BUGS.md` entries are VaRs (see `BUGS.md`).
- `optionpricing/hedging/` — the Deep Hedging rebuild's non-ML building blocks, shared by training, evaluation and the baselines so that every policy is booked and scored by the same functions. Built so far:
  - `risk.py` — torch risk measures of a 1-D batch of terminal P&Ls, differentiable so a training loss backpropagates through them. `cvar(pnl, alpha=0.95)`, the average of the worst `1 - alpha` share on the P&L scale (higher is better), the reported metric. When `(1 - alpha) * n` is fractional, the edge path counts for its share. `cvar_loss(pnl, w, alpha=0.95)`, the Rockafellar-Uryasev training form `w + mean(relu(-pnl - w)) / (1 - alpha)`, a loss whose minimum over `w` is `-cvar` for any batch size. `entropic(pnl, lam)`, `(logsumexp(-lam * pnl) - ln n) / lam`, so `e^{-λ PL}` never overflows. `variance(pnl)`, the `1/n` form (0 for one path). A list or array becomes float64, a tensor keeps its dtype and graph. Empty or non-1-D input, `alpha` outside (0, 1), a non-scalar `w` and a non-positive or non-finite `lam` raise `ValueError`. Tests in `tests/unit/test_risk.py`.
  - `costs.py` — `transaction_cost(trade, spot, proportional=0.0, fixed=0.0, kappa=None)`, elementwise `proportional * |trade| * spot + fixed * 1[trade != 0]` with `trade` and `spot` broadcast. The fee is straight-through (`hard + (soft - soft.detach())` with `soft = 1 - exp(-|trade| / kappa)`): the forward value is the exact fee, the gradient in `trade` is `fixed * sign(trade) * exp(-|trade| / kappa) / kappa`, 0 at `trade = 0` (`docs/results/hedging-training.md`). `kappa` is required only when `fixed > 0` and `trade` needs a gradient, so evaluation under `torch.no_grad()` can leave it out. A list or array becomes float64, a tensor keeps its dtype. Negative or non-finite rates, a non-positive or non-finite `kappa`, and a missing `kappa` when the fee needs a gradient raise `ValueError`. Tests in `tests/unit/test_costs.py`.
  - `settlement.py` — what ending the short put costs the hedger, `Z` in the P&L: the payoff plus the closing trade, priced by `transaction_cost`. `cash_settlement(spot, position, strike, proportional=0.0, fixed=0.0, kappa=None)` pays `(strike - spot)^+` and closes `position` shares. `physical_settlement(...)` (same arguments) pays `strike - spot` for the delivered share and closes `position + 1` shares when `spot < strike`, and closes `position` shares otherwise (the put lapses; at `spot == strike` neither settlement delivers). Both are elementwise with broadcasting, equal before costs, and differentiable in `position`. Non-positive `spot` or `strike` raises `ValueError`, and invalid cost settings raise as in `transaction_cost`. Tests in `tests/unit/test_settlement.py`.
  - `simulator.py` — `simulate_scenarios(n_contracts, paths_per_contract, seed, days_range, sigma_range, rate_range, moneyness_range, strike=100.0)` draws `n_contracts` put contracts uniformly (days to expiry a whole number in `days_range`, both ends included; `sigma`, `r` and `S_0/K` in their ranges) and simulates `paths_per_contract` daily price paths for each with one per-contract `GBM` call, using one `np.random.default_rng(seed)` for the draws and the paths. A scenario is one contract with one of its paths. The ranges have no defaults: the dataset generator owns the contract family. Returns a frozen `ScenarioBank`: `spot` of shape `(n_scenarios, max(days) + 1)`, one row per scenario with time last, on one daily grid (`DAYS_PER_YEAR` = 365), NaN after each scenario's expiry; `contract`, the contract index of each scenario, grouped by contract; the per-contract `days`, `sigma`, `risk_free_rate`, `moneyness`; `strike`; and the properties `maturity` (`days / 365`) and `times` (years per step). A per-scenario value is `bank.sigma[bank.contract]`, and per-contract work (a tree price, a boundary) is shared by the contract's paths. Invalid counts, strike or ranges raise `ValueError`. Tests in `tests/unit/test_simulator.py`.
  - `exercise.py` — the day `τ` each scenario's holder ends the put. `daily_boundary(bank, nb_steps=1000, chunk_size=None)` runs one `exercise_boundary` tree per contract and reads `S*` off at every day by linear interpolation in time, in dollars at `bank.strike`: shape `(n_contracts, max(days) + 1)`, on the columns of `bank.spot`, the strike at expiry, NaN after it, and NaN before it when `r <= 0`. `exercise_days(bank, method, boundary=None, shift=None)` returns an int `τ` per scenario, between 0 and its days to expiry, for a method in `METHODS`: `tree`, the first day with `S_k <= S*_k` (day 0 included); `late`, the same against `(1 - shift) S*` with `shift` in (0, 1); `lsm`, the plain `LongstaffSchwartz` put rule (cubic `simple` basis, no control variate) fitted on each contract's own paths, in sample as the legacy hedger did; `never`, the expiry. A put not exercised early gets its expiry, in or out of the money: settlement decides whether it pays. `boundary` is computed when None, so a caller that stores it passes it in. An unknown method, a `shift` missing or outside (0, 1) with `late` or given with another method, a `boundary` given with `lsm` or `never` or of the wrong shape raise `ValueError`. Tests in `tests/unit/test_exercise.py`, among them the mean discounted payoff at the `tree` dates against the tree's American price and at the `never` dates against Black-Scholes.
  - `pnl.py` — `hedge_pnl(policy, inputs, spot, tau, premium, strike, rate, rebalance_every=1, settlement="cash", proportional=0.0, fixed=0.0, kappa=None)`, the one place the hedging accounting lives: training, evaluation and the baselines all call it. It books each path's terminal P&L in dollars of `t_0`, `p_0 + Σ_j δ_j (S̃_{t_{j+1}} - S̃_{t_j}) - Σ_j e^{-r t_j} c_j - e^{-r τ} Z_τ` with `S̃_t = e^{-r t} S_t`, so the cash account at `r` is implicit. A policy is any callable `policy(inputs, position) -> position` on `(nb_scenarios, nb_features)` features and the `(nb_scenarios,)` position held, called once per hedge date (days `0, m, 2m, ...` before `τ`, `m = rebalance_every`); the position chosen at `t_j` earns from `t_j`, and the last one earns until `τ`, cut short on a coarse grid. `inputs` is `(nb_scenarios, nb_features, n_days)` and `spot` `(nb_scenarios, n_days)`, time last; `tau` is an int day per path in `[0, n_days - 1]` (`τ = 0` settles at once with no hedge). Past `τ` a path keeps its position, trades nothing, and its features are zeroed before the policy sees them, since a NaN fed to the network makes its gradients NaN even where the output is discarded. Returns a `HedgeOutcome(pnl, costs, positions)`: `costs` are the discounted trading and closing-trade costs, so the costless P&L minus the costly one equals them; `positions` is `(nb_scenarios, n_dates)`. A shape mismatch, `tau` out of range or not ints, `rebalance_every` not an integer >= 1 (numpy integers are accepted), an unknown `settlement` or a policy returning the wrong shape raise `ValueError`, as do invalid costs and settlement prices. Tests in `tests/unit/test_pnl.py`: no hedge against `p_0 - e^{-r τ}(K - S_τ)^+`, a cash account booked day by day, the B-037 timing, and the daily Black-Scholes delta hedge of a European put at std P&L / K ≈ 0.0035 (B-038), doubling when rebalancing every 4 days.
  - `baselines.py` — the policies the network is measured against, with its interface, so `hedge_pnl` books them and `risk.py` scores them. They read one input layout, `BASELINE_FEATURES` = (`spot` in dollars, `delta` in shares, `gamma` = `d2V/dS2` in shares per dollar, `time_left` in years, `rate`), stacked by `baseline_inputs(spot, delta, gamma, time_left, rate)` into a float64 `(nb_scenarios, 5, n_days)` tensor (the others broadcast to `spot`'s shape; a gamma per unit of strike is divided by the strike first). `no_hedge` holds nothing. `delta_hedge` holds the `delta` row: fed the surrogate's deltas it is the surrogate delta hedge, fed the tree's the tree delta hedge. `band_hedge(half_width, target="edge")` holds while `|δ_{k-1} - Δ_k| <= half_width` (exactly, so no fixed fee is charged; the edge counts as inside) and otherwise trades to the nearest edge (`"edge"`) or to delta (`"delta"`). `whalley_wilmott(risk_aversion, proportional, target="edge")` is the same band with the half-width of `whalley_wilmott_half_width`, `(3/2 · e^{-r (T - t)} · ε S Γ² / γ)^{1/3}` (Whalley and Wilmott 1997), used with the American put's gamma, so it closes in the exercise region; `proportional` is the rate the band is built for, not the cost charged. `tune(make_policy, grid, score)` builds a policy per grid value, rates it with `score` (higher is better, e.g. `cvar` on validation paths) and returns `(best, scores)`, ties to the first value. A negative or non-finite width, risk aversion or rate, an unknown target, an empty grid or a non-finite score raise `ValueError`. Tests in `tests/unit/test_baselines.py` (the band's exact hold, its edges, the Whalley-Wilmott width by hand and its cube-root scaling, fewer fixed fees than the delta hedge) and `tests/integration/test_baselines_vs_tree.py`: on American puts hedged at tree deltas against the `tree` holder with the tree premium, the mean P&L at zero cost is 0 within 4 standard errors, the daily delta hedge leaves under a tenth of the unhedged spread and doubles its error when rebalancing every 4 days, and both bands beat delta hedging on CVaR at a 1% cost.
- `optionpricing/ml/experiments/` — research drivers, not CLI commands, run as modules from the project root. `run_ablations.py` (`python -m optionpricing.ml.experiments.run_ablations [--variants ...] [--seeds ...] [--jobs 4 --threads 2] [--out_dir artifacts/runs/ablations]`): the surrogate's seeded ablations (`docs/results/surrogate-training.md`). `VARIANTS` maps a name to the `TrainConfig` fields it changes from `ABLATION_BASE` (`lambda_delta` 1, linear output: the defaults the ablations were measured against, pinned so that `TrainConfig`'s new defaults change no variant or stored run) (one each; `baseline` none; each `COMBINED` entry, such as `lambda_delta_0.3_softplus`, joins the changes of the one-change variants it names), run for each of `SEEDS` (42, 43, 44) in `--jobs` worker processes of `--threads` torch/BLAS threads (4 x 2 is ~2.8x one 8-thread run: the 50k-weight net uses threads poorly), the slowest variants first (`run_cost`: the shape penalty and a width above `TrainConfig`'s default, such as `width_256` and `lambda_delta_0.3_softplus_width_256`, rank 2 each, the L-BFGS finish 1). `DATASET_VARIANTS` maps a name (`T_from_0.25`, `exercised_0.25`) to a base variant whose config it trains and a directory next to `--dataset_path`'s holding its own `tree_put_dataset.npz` (`dataset_path_for`), made with the generator's `--T_min 0.25` and `--exercised_keep 0.25`; they run only when named in `--variants`. `--grid_T_min` scores every run on the grid over the `--dataset_path` domain with its T range starting there (stored in the evaluation settings only when given, so earlier runs still count as done; give it its own `--out_dir`). Before any run, `check_dataset` checks each variant's dataset: it exists (`FileNotFoundError` naming the generator), the reference tree is not its teacher, and its domain covers the grid (`ValueError` otherwise). Each worker calls `train_surrogate` and `evaluate_test_split`/`evaluate_grid` directly (the shared `reference_grid.npz`, computed once by the main process before the workers start) and writes `<out_dir>/<variant>/seed_<seed>/`: `model.pth`, `history.json`, `report.txt` (`print_report`), `log.txt` (its progress bars) and, last, `metrics.json` (with `dataset`, the dataset's path, generator settings and domain: `dataset_info`), which marks the run done: a rerun skips it, and refuses (`ValueError`) one whose stored config or evaluation settings differ. A failed run writes `error.txt` and the others go on (exit code 1). `summary.md` (`collect_results`: every finished run in `--out_dir`, not only the requested variants and seeds): per variant, mean ± sample sd over seeds of the grid and test-split errors, violation rates at both tolerances, the best entry's validation premium/delta terms and the training time. `--epochs` and the grid flags exist for smoke runs. On Windows the whole run is wrapped in `keep_awake()` (`SetThreadExecutionState` system + display required, released after, also on Ctrl-C): this PC uses Modern Standby, where the screen turning off suspends programs whatever the sleep setting (`BUGS.md`), so the display stays on during a run. Outputs in `artifacts/runs/` (gitignored).

## Working notes

- Always run scripts from the project root — imports are absolute against the repo root (e.g. `from optionpricing.core.gbm import GBM`), not package-relative. `python -m optionpricing.ml.surrogate.tree.generate_tree_dataset` is required (not `python optionpricing/ml/surrogate/tree/generate_tree_dataset.py`) for the same reason.

- When touching normalization logic, keep `optionpricing/ml/surrogate/legacy/generate_lsm_dataset.py`'s normalization (log-sigma, log-T, raw-r) consistent with `optionpricing/ml/surrogate/legacy/lsm_dataset.py`'s `AmericanOptionDataset` — they must agree for the legacy MLP's inputs to be meaningful (the tree MLP has one `build_features`, so nothing to keep in sync).
- `scripts/test_ml.py` takes the teacher's `method`/`nb_steps` from the tree dataset `.npz` only to refuse a reference tree with the same settings: scoring against the teacher would measure how well the net copies it, errors included.

- Checkpoint and dataset paths are constructor/CLI arguments with `artifacts/checkpoints/`/`artifacts/data/`-relative defaults, not hardcoded absolute paths — pass `--checkpoint_path`/`--dataset_path`/etc. rather than editing defaults in place if you need a different location for one run.
- Path-scoped conventions (e.g. progress-bar requirements for long-running loops) live in `.claude/rules/` and auto-apply on matching paths — check there for anything not covered in this file.


## Design notes

### Softplus reparameterization: general pattern for ML regression targets

When an ML model's *target* is defined as `true_value - analytic_component`
(a common trick to shrink dynamic range or remove a known effect before
regression, e.g. `time_value = price - intrinsic_value` here), check whether
`analytic_component` has a kink (a point where it's continuous but its slope
jumps) that `true_value` does *not* have at that same point. If so, subtracting
it stamps that kink onto the residual as an artifact — the model's error will
spike specifically in a band around that point, easy to mistake for "this
region is intrinsically harder to model" when it's actually self-inflicted by
the label definition.

This is exactly what happened with `smooth_intrinsic_value` in `optionpricing/ml/surrogate/legacy/lsm_model.py` —
see `.claude/BUGS.md`, "ML surrogate pricer's target had a self-inflicted
kink at ATM" for the full incident (symptom, root cause, evidence, fix).

**Fix pattern**: replace the exact analytic component with a *smooth*
approximation that converges to it away from the kink but rounds off the
corner over a small window (here, a softplus: `smooth_intrinsic_value` in
`optionpricing/ml/surrogate/legacy/lsm_model.py`). Use the *same* smooth version consistently
wherever the component is added back to reconstruct the true value
(`optionpricing/ml/surrogate/legacy/lsm_evaluation.py::test_option_price_lsm`) - training and reconstruction must
agree, or predictions will be systematically biased. The smoothing width is a
hyperparameter with a real trade-off (too little: kink barely smoothed, error
stays high near it; too much: the smoothing correction bleeds into regions
that didn't need it and degrades them instead) — pick it by sweeping a few
values against a fixed benchmark, with training runs fully seeded (model init,
data split, batch shuffling) so you're comparing the hyperparameter's effect,
not run-to-run training variance.

**When to reach for this pattern again**: any time you're about to subtract
(or divide by) an analytic function from an ML target to make it easier to
learn, ask "does this analytic function have a kink/discontinuity that the
real target doesn't have at that point?" before shipping it.
